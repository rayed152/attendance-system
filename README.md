# Cross-Platform Desktop Attendance Management System

A simple, secure, cross-platform desktop application for recording employee/user **Entry** and **Exit** attendance events. Built with **Electron**, **React**, **TypeScript**, **Tailwind CSS**, **Prisma ORM**, and **Neon PostgreSQL**.

---

## Architecture Overview

```text
React Renderer (Vite + Tailwind CSS)
        │
        │ ContextBridge (Secure IPC API layer)
        ▼
Electron Main Process (Node.js + TypeScript)
        │
        │ Prisma ORM (Parameterized & Database-Safe Queries)
        ▼
Neon PostgreSQL (Cloud Database)
```

---

## Features

- **Cross-Platform**: Runs natively on **Windows** and **Linux**.
- **Secure Authentication**: User ID & password login with passwords hashed via `bcrypt`.
- **Session Persistence**: Session stored in memory in the Electron Main process.
- **Trusted Timestamps**: Entry/Exit timestamps are generated by the backend engine rather than relying on frontend client time.
- **Smart Sequence Rules**:
  - Blocks accidental double clicks.
  - Rejects duplicate Entry attempts if already checked in.
  - Rejects Exit attempts if there is no active Entry.
- **Attendance History**: View past attendance events with precise dates, event types (`ENTRY` / `EXIT`), and timestamps.
- **Isolated Renderer**: Database credentials and Prisma ORM are strictly hidden inside the Electron Main process.

## 1. Prerequisites

Before installing the project, ensure you have the following installed on your host system:

- **Node.js**: v18.0.0 or higher (v20+ recommended)
- **npm**: v9.0.0 or higher
- **Git**
- **Neon PostgreSQL Account**: Free tier available at [neon.tech](https://neon.tech)

---

## 2. Neon Database Setup

1. Sign up or log into [Neon PostgreSQL](https://neon.tech).
2. Create a new PostgreSQL database project (e.g., `attendance-db`).
3. Copy the pooled PostgreSQL connection URI provided in your Neon dashboard.
   - Example connection string format:
     `postgresql://username:password@ep-sample-12345.us-east-2.aws.neon.tech/neondb?sslmode=require`

---

## 3. Environment Variable Setup

1. Copy `.env.example` to `.env`:
   ```bash
   cp .env.example .env
   ```
2. Open `.env` in your code editor and replace `DATABASE_URL` with your actual Neon PostgreSQL connection string:
   ```env
   DATABASE_URL="postgresql://username:password@ep-sample-12345.us-east-2.aws.neon.tech/neondb?sslmode=require"
   ```

> [!IMPORTANT]
> **Never commit your `.env` file to source control.** It is automatically ignored in `.gitignore`.

---

## 4. Installation

Install all project dependencies using npm:

```bash
npm install
```

---

## 5. Prisma Setup & Code Generation

Generate the Prisma Client JS engine from `prisma/schema.prisma`:

```bash
npm run prisma:generate
```

---

## 6. Database Migration

Run the Prisma migration tool to apply the schema (`User`, `Attendance`, `AttendanceType` enum, and composite indexes) to your Neon database:

```bash
npm run prisma:migrate
```

*(You will be prompted to enter a migration name, e.g. `init`)*

npm run dist

- Installer file: `release/Attendance System Setup 1.0.0.exe`

*(Note: Windows binaries can be built on Linux/macOS using Wine or directly on a Windows machine)*

## 11. Linux Build

To generate an AppImage standalone package for Linux:

```bash
npm run dist
```

- Target output directory: `release/`
- AppImage file: `release/Attendance System-1.0.0.AppImage`

To make the AppImage executable on Linux:
```bash
chmod +x "release/Attendance System-1.0.0.AppImage"
./"release/Attendance System-1.0.0.AppImage"
```

## 12. Troubleshooting

### 1. Connection Error (`P1001: Can't reach database server`)
- Verify your internet connection.
- Check that your `DATABASE_URL` in `.env` is correct and contains `?sslmode=require`.
- Ensure Neon project is active and not paused.

### 2. Missing Prisma Client
- Run `npm run prisma:generate` to regenerate the Prisma client typescript artifacts.

### 3. IPC Channel Errors
- Ensure you compiled the main process by running `npm run build:electron` or starting dev mode via `npm run dev`.
